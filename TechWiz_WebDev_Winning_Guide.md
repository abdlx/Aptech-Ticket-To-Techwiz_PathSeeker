& Development category, along with practical tips to build a project
that stands out to judges.

## 2. Understanding and Executing the SRS

In TechWiz, the project topic and SRS (System Requirements
Specification) are provided by Aptech --- teams do not choose their own
idea. Winning depends on how completely and accurately the given SRS is
executed, not on how creative the idea is.

-   **Break the SRS into a checklist:** turn every requirement into a
    task so nothing is missed.
-   **Do not skip requirements to add extra features:** judges score
    against the SRS --- unrequested features do not make up for missing
    ones.
-   **Clarify ambiguous requirements early:** if something is unclear,
    ask if possible; otherwise note your interpretation in the
    documentation.
-   **Assign clear ownership:** split SRS modules among team members so
    every requirement has one person responsible for it.

> **Note:** Since this category has no Database Testing parameter, most
> SRS requirements will focus on front-end design and client-side
> (JavaScript) functionality rather than backend features.

## 3. Features That Impress Judges

-   **Interactivity:** search/filter tools, live form validation,
    calculators, quizzes, dark mode toggle
-   **Smooth UX:** clear navigation, scroll animations, consistent
    layout across pages
-   **Accessibility:** alt text on images, keyboard navigation, strong
    color contrast, screen-reader-friendly structure
-   **Mobile-first design:** design for phone screens first, then scale
    up to tablet and desktop
-   **Polish over scope:** a few features done perfectly score higher
    than many features half-finished

## 4. Preparation Timeline

-   **Day 1:** Read the SRS fully and break it down into a task
    checklist
-   **Day 1--2:** Wireframe the pages and plan the folder/file structure
-   **Development phase:** Build page by page; assign clear tasks to
    each team member
-   **2 days before deadline:** Functionality testing + cross-browser
    testing (Chrome, Firefox, Edge, Opera)
-   **Throughout:** Write documentation in parallel --- do not leave it
    for the last day
-   **Final day:** Review everything, fix bugs, and submit early --- not
    at the last minute

## 5. Common Mistakes to Avoid

-   Leaving documentation until the last minute
-   Testing on only one browser
-   Copying design or code from existing websites (plagiarism check will
    catch this)
-   Overloading the site with features that are not fully finished
-   Missing folder structure conventions (`images/`, `css/`, `js/`)
-   Submitting after the deadline --- this is an automatic point loss

## 6. Final Checklist Before Submission

-   [ ] All SRS requirements implemented and working
-   [ ] Responsive on mobile, tablet, and desktop
-   [ ] Tested on Chrome, Firefox, Edge, and Opera
-   [ ] Code is clean, commented, and properly organized in folders
-   [ ] Project report completed with diagrams and task distribution
-   [ ] No copied content --- everything is original
-   [ ] Submitted before the deadline
